# Session-owned Claude command hooks

Immutable baseline: `vendor/sources/extensions`, GitHub Release `dsh-extensions@0.1.3-dsh.0.2.1-rc.5`, upstream `gulagala001/dsh-extensions`, archive SHA-256 `e20bff8aa1694d2a2c666e554f5cc1a972e7bb744ca90b498171b949f93593a3`. `baseline.json` records every original file hash. `files/` contains the reviewed replacement source; `apply.mjs` validates all affected originals before writing a staged copy and records before/after digests. It refuses a live `.dsh/profiles` target. After patching, run the existing `npm run build` in GitHub Actions for the hook editor's real-session try-run selector; no local builds or new tests were added.

Extensions remains the sole dispatcher. Keep `dsh-claude-compat.enableHooks: false`; do not mount `dsh-hooks-claude-code` as another engine. The native hook-protocol runner/codec/merge are library dependencies only. Requires native rc.5 plus the reviewed `PreToolDecision.updatedInput` patch.

Runtime dependency: `platformProjectConfig.resolve(agent,signal)` returns verified source and execution roots plus actual preset-owned fs/subprocess/sandbox/shell/sandboxPolicy. Its `writeState(agent,'transcript.jsonl',text,signal)` writes the derived Claude-format protocol projection into configured private executor state. It does not create or replace a native Session. Missing executor state configuration is an activation error, not permission to write into the Host home or a repository.

Sources are mapped user `.dsh/hooks.json` and `.claude/settings.json` only under the explicit executor user configuration root, then versioned project `.claude/settings.json` from the actual checkout, then local `.claude/settings.local.json` from the stable source root. The legacy DSH path remains available for unbound local sessions. A bound executor never reads the control host's home implicitly. Changes are read through the bound filesystem at the next event. Imported files are never copied over canonical Claude files.

Each resolved hook captures its own origin and `projectDir`: versioned settings use `checkoutRoot`, local settings use the stable `sourceRoot`, and skill-scoped/global/native DSH hooks use `checkoutRoot` unless their registration explicitly supplies another project directory. `CLAUDE_PROJECT_DIR` follows that captured origin; process cwd and JSON `cwd` always use the actual task directory. Async execution retains the same origin and executor context. No configuration/assets are copied into task checkouts.

Command hooks support shell and argv forms, per-command timeout, async/asyncRewake, once, tool aliases, context, blocking, native ask, updatedInput, and skill invocation-scoped registration. `Hooks.registerSkill(agent,{id,source,pluginRoot,hooks})` returns its disposer. The native skill adapter owns admission and removal; the dispatcher does not register a second event pipeline. Actual Windows realms, including bound `local-pilot`, use configured native Git Bash/PowerShell paths; SSH Linux uses its own realm shell. The WSL Bash launcher is rejected as a Git Bash replacement.

SessionStart runs at first admitted turn before its model request. Stop uses actual `stop_hook_active`, carries feedback, and has no arbitrary three-continuation cutoff; cancellation still terminates work. SessionEnd cleanup is registered after preset setup and drains before provider teardown; it cannot request approval outside an open turn. Git Bash IPC initialization failure can request one native approval for one retry of that exact configured command. No session-wide permissions, persistent grants, Host process fallback, or additional retry loop is installed.

The hook transcript projects the full native journal, including messages removed from the current model context, original native events and PTC tool calls/results. Actual slash commands and committed skill invocations supply Claude command markers such as `/review`; failed skill loads do not create an invocation. Stop receives the last published assistant text and live native workspace activity as `background_tasks`, retaining the native kind and actual identifiers. This projection never replaces or rewrites the Session.

Non-command hook types are rejected explicitly. They are not silently omitted or run through paid model calls. Actual deployment, VM provisioning, physical phone pairing and live installation changes are separate activation work.
